# Versioned VFX assets

Use the existing project's STYLE and ENGINE. This workflow supplies reusable effect packages and phase evidence alongside the visual pipeline; it never selects another primary pipeline or backend.

Read [the command guide](../../../docs/VFX_ASSETS.md) for exact contracts and examples. Start with `vfx-assets.sh doctor`, then `init` an asset/version beneath the active task. Capture camera/view distance, model-relative size and attachments, release/impact timing, occupied and clear screen regions, blending, finite budgets, quality/accessibility variants and declared targets. Bind applicable model, rig, clip, marker and transform files by their actual hashes.

Stage a provisional package with its complete capture/environment packet. Bubo checks data-only descriptors and the exact resource closure; Hephaera retains immutable inputs and binds the whole review packet. A missing driver/camera/settings identity or incomplete capture coverage is unavailable evidence, never an accepted visual review. A distinct independent reviewer records acceptance or rejection against the exact current packet and separately hashed source evidence. Detailed staging requires current provisional acceptance.

Revisions retain failed attempts, rejected reviews and ancestry. A changed brief, input, rights record, policy, native build, scene, camera, driver or artifact invalidates affected evidence. Do not change expected hashes to refresh a review. Preserve declared candidate/revision bounds and existing shared MEDIA permissions/attempts.

After interruption, inspect ownership and incomplete reservations. Use the scoped `recover` operation only when it can verify the retained writer has ended; keep archived lock/attempt evidence and spent budgets. It never kills a process or establishes untracked native-child cleanup.

The initial command handles owned/licensed fixed inputs. Generated-receipt admission is explicitly unavailable; inspecting a MEDIA contract or supplied receipt cannot mint a generation allowance. Resource preparation, runtime rendering, reusable-package action integration and promotion require their later declared capability and actual target evidence. No standalone package, staged visual packet or independent technical review grants human runtime acceptance.
