# Build Image-to-Splat Assets

## When to use

Use when the deliverable is a static Gaussian object whose complete intended viewing range can be reviewed. For engineered articulation, dimensioned mesh accuracy or capture reconstruction, select the corresponding workflow instead.

## Workflow

1. Resolve this skill, read the host's `STYLE.md` and `MEDIA.md`, and explicitly select the optional image-to-splat workflow under `LOCAL`. Record task-local LOCAL selection when the primary differs. Preserve the primary visual pipeline, engine and independent AUDIO/MUSIC/VOICE domains. Read `docs/IMAGE_TO_SPLAT.md` in the Hephaera installation for current command and evidence contracts.
2. Define a static object's intended views, appearance and output budgets. Inspect configured external asset libraries before creating a replacement; follow their read-only/copy rules. Use one exact rights-cleared project-local image. Generated hidden surfaces remain predictions: the source does not establish physical dimensions, functional internals, independent parts or unseen-side truth.
3. Use `image-to-splat.sh` to initialize an immutable asset version and inspect prerequisites without loading a model. Bubo owns technical schemas, model/tool pins, setup and execution. Read its verified image-to-splat resources rather than maintaining another model manifest or substituting a sibling checkout.
4. Keep acquisition and installation registration separate from generation. Prepare their dry-runs first; execute only with applicable installation authorization and exact component licence/access records. TripoSplat's MIT licence does not replace DINOv3, FLUX autoencoder, BiRefNet or native-component obligations. Setup accepts no terms and changes no drivers implicitly.
5. Bind actual source rights, current STYLE/selection, installation/catalogue, settings and finite process/input/output/memory allowances before generation. Record the user's source-bound candidate/revision approval and current GPU availability. First use also needs a reviewed ledger-history registration with the operator's real decision: never infer fresh history from missing files. Retain its receipt/evidence, the canonical project-shared media-state root independently of approval changes, and original native task/source/approval bindings across versions. Existing, differing or multiple historical roots require the guide's explicit history checks; do not migrate or upgrade an unregistered binding automatically.
6. Generate only the authorized candidate or reviewed revision through the verified Bubo boundary. Keep the exact source, request, settings, build/environment and claim ancestry with separately identified density variants in non-runtime staging. A failed pipeline stops for direction; do not install, retry or change backend, precision, device or representation automatically.
7. Independently verify the exact generated package. Structural artifact validation and PLY inspection alone do not authenticate construction history. Preserve the producer build used by the package; a new commit/build cannot relabel historical output or renew its approvals. Reconciliation after an interrupted or failed run is a separate reviewed operation, retaining the original outcome and spent claim.
8. Review the original image beside the complete density/view package, including non-input views. Check silhouette, foreground separation, holes, floaters, thin features, invented surfaces and the declared coordinate/scale uncertainty. Record independent review and a separate actual human backend verdict with explicit caveats against the exact current package and evidence. Technical success never supplies those decisions.
9. Use `status` for continuation. Revise through a new immutable version with retained parent ancestry; changes to source, settings, model/environment, STYLE or output invalidate affected verification and review. After failure, stop for actual user direction. A new parented candidate after no successful result preserves original ownership and leaves Bubo to arbitrate any spent claim; it never permits an automatic or same-version retry. Failed, cancelled and uncertain claims remain spent. Keep receipts, rejected attempts and private inputs intact.

## Handoff

Deliver the typed Gaussian package, original/configuration ancestry, verification and current review evidence. The Gaussian scene is the source artifact; it is not a detailed editable Blender mesh. The native pilot qualifies supplied-alpha RGBA inputs on a measured Windows/RTX 5080 profile only. Other segmentation paths, hosts and settings need their own evidence.

Renderer integration, Spark/Three.js, packaged MAUI/device performance, physical scale, collision, animation, game acceptance, asset promotion and public disclosure remain separate operations. This skill grants no runtime installation or promotion authority.
